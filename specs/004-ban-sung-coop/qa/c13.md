## Cross-Check Findings

1. **[MINOR] `BansungRateLimiter` `'config'` token bucket is unused in lobby RPC paths**
   - `server/src/game/bansung/security.ts` (`BANSUNG_SEC_LIMITS`) defines `CONFIG_BUCKET_CAP: 5` and `CONFIG_REFILL_PER_SEC: 1`, and `BansungRateLimiter.consume(playerId, 'config', nowMs)` implements the bucket.
   - At runtime, `BansungRateLimiter` is instantiated per match inside `BansungWorld` (`server/src/game/bansung/world.ts:751`), not in `Game` or `RoomsService`.
   - Consequently, lobby handlers `bansung:config` (`server/src/game/game.gateway.ts:335-343` -> `server/src/game/game.ts:1718-1768`) and `bansung:hero` (`server/src/game/game.gateway.ts:345-348` -> `server/src/game/game.ts:1777-1789`) enforce `validateBansungConfig`, `validateBansungHero`, host authorization (`requireLobbyHost` for config), and no-op equality early return on hero selection, without per-player token-bucket throttling via `BansungRateLimiter`.

2. **[MINOR] Non-object / missing-`t` `bansung:cmd` envelopes fail before `recordViolation`**
   - `server/src/game/game.gateway.ts:325-333` (`bansung:cmd`) and `server/src/game/game.ts:1791-1804` (`bansungCommand`) reject `!rawCmd || typeof rawCmd !== 'object' || typeof rawCmd.t !== 'string'` by throwing `GameError` directly (which emits `'toast'` to the client).
   - Because these envelopes never reach `this.bansung.enqueueCommand(playerId, rawCmd)` (`server/src/game/bansung/world.ts:1236-1290`), they do not increment `BansungRateLimiter.recordViolation` toward the `VIOLATION_KICK_COUNT = 20` / `VIOLATION_WINDOW_MS = 5000` kick threshold (whereas malformed payloads with a string `.t`, including `Array` instances with `.t` assigned, fail inside `enqueueCommand` and count toward violations).

3. **[MINOR] `applyGachaPick` defensive `pickIdx` clamp & `seq: 0` repeat acceptance**
   - `server/src/game/bansung/security.ts:283-289` strictly rejects any non-integer or out-of-range gacha pick (`pick < 0 || pick > 2`) with `invalid_gacha_pick`.
   - `server/src/game/bansung/world.ts:2920-2978` (`applyGachaPick`) guards against empty/absent `p.gachaChoices` and defensively clamps `pickIdx` to `[0, p.gachaChoices.length - 1]`. Under normal 3-card drafts (`rollSurvivalGachaCards`), `0 | 1 | 2` maps 1:1; if a smaller draft array were ever generated, `pick: 2` would clamp to the last card instead of rejecting.
   - `createPlayerActionGuard()` (`server/src/game/bansung/security.ts:570`) initializes `lastAckSeq = 0`, and `world.ts:1303` drops commands only when `cmd.seq < player.guard.lastAckSeq`, intentionally allowing repeated `seq: 0` packets before monotonic sequence numbers advance.

4. **[MINOR] Early security spec `d48-security-validation.md` module & constant drift**
   - `specs/004-ban-sung-coop/design/d48-security-validation.md` references historical file names (`validate.ts`, `static-guard.ts`) and an earlier `CMD_BUCKET_CAP` draft (`20`).
   - Implementation is cleanly consolidated in `server/src/game/bansung/security.ts` and `server/src/app.module.ts`, with `BANSUNG_SEC_LIMITS.CMD_BUCKET_CAP` / `CMD_REFILL_PER_SEC` aligned 1:1 to `shared/src/bansung/types.ts` (`BANSUNG_CMD_BURST = 45`, `BANSUNG_CMD_REFILL = 35`).

## Verified Invariants

- **Survival Gacha `0 | 1 | 2` & Life-State Checks**:
  - `validateBansungCommand` (`server/src/game/bansung/security.ts:283-289`) uses `finiteNumberOrNull(raw.pick)`, rejects non-integers and values outside `[0, 2]` with `{ ok: false, reason: 'invalid_gacha_pick' }`, and narrows output to `{ t: 'gacha', pick: pick as 0 | 1 | 2 }`.
  - `DEAD_OR_DOWNED_ALLOWED_CMDS` (`security.ts:58-64`) permits `'in' | 'perk' | 'gacha' | 'ping' | 'spec'` while downed/dead and blocks `'use'`, `'slot'`, `'gadget'`.
  - `applyGachaPick` (`world.ts:2920-2978`) executes only when `p.gachaChoices` is non-empty and applies either `weapon_upgrade` or `applySurvivalGachaSkillToHero`.
- **Prototype-Pollution & Payload Budget Guards**:
  - `FORBIDDEN_PROTO_KEYS = Set(['__proto__', 'constructor', 'prototype'])` (`security.ts:66-70`).
  - `isSafePlainObject` (`security.ts:88-110`) enforces non-null non-array objects with `Object.prototype` or `null` prototype, checks own keys via `Object.prototype.hasOwnProperty.call(obj, key)` against `FORBIDDEN_PROTO_KEYS`, and caps key counts (`MAX_CMD_KEYS = 8` for commands, `16` for config, `4` for hero).
  - `isWithinJsonByteBudget` (`security.ts:116-127`) enforces UTF-8 serialized byte limits (`MAX_CMD_JSON_BYTES = 512`, `MAX_CONFIG_JSON_BYTES = 1024`) in a `try/catch`.
  - `validateBansungConfig` (`security.ts:335-346`), `validateBansungHero` (`security.ts:353-370`), `validateBansungCommand` (`case 'perk'`, `security.ts:266-281` with `/^[a-z0-9_]+$/` + `MAX_PERK_ID_LEN = 48` + `getBansungPerk`), and `pickups.ts:953` (`Object.prototype.hasOwnProperty.call(registry, perkId)`) prevent prototype chain lookup or pollution.
- **Arena `4224x2688` Clamping, Input Normalization & Combat/Pickup Locks**:

  - Beyond coordinate clamping, `activateGadget` (`server/src/game/bansung/gadgets.ts:845-925`) enforces alive/!downed/!stunned/charge/energy checks, clamps throw/deploy offset via `clamp(rawDist, spec.minRange, spec.maxRange)` (L891) around the player, and resolves walls with `pullPointOutOfWalls`.
