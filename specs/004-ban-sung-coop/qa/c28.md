### [MINOR] Control & Revive Keybind Copy Mismatch (`Rules.tsx`, `Lobby.tsx`)
- **Files**: `client/src/components/Rules.tsx:165`, `client/src/components/Lobby.tsx:822`
- **Issue 1 (`Q / 4–5 dùng đồ hỗ trợ`)**: `Rules.tsx:165` states keys `1–3 / Cuộn chuột` switch weapons while `Q / 4–5` use support items. In runtime (`client/src/bansung/input.ts:417-441, 1278-1290`), `Digit1`–`Digit5` all call `selectSlot(0..4)` (`{ t: 'slot', idx }`, backed by `switchHeroWeaponSlot` with `BANSUNG_MAX_WEAPON_SLOTS = 5` in `server/src/game/bansung/weapons.ts:113, 764-778`), while `KeyQ` triggers `BANSUNG_BTN_SKILL` -> `{ t: 'gadget', x, y }` (`input.ts:983-996`). Likewise, `client/src/components/bansung/HotbarShop.tsx:1259, 1277, 1362, 1391, 2437-2464` binds `Q` to `<GadgetHotbarSlot>` (though its tooltip string at `HotbarShop.tsx:1259` also still says `[Q / 4]`), renders 3 weapon slots `[0, 1, 2]` (`input.ts:1181` clamps mouse-wheel cycling to 3 slots), and uses slots `4`/`5` for extra weapon/supply slot rather than gadget activation.
- **Issue 2 (`E nhặt vũ khí / cứu đồng đội`)**: `Lobby.tsx:822` (`"E nhặt đồ hoặc cứu đồng đội"`) and `Rules.tsx:165` (`"E nhặt vũ khí / cứu đồng đội"`) claim `E` revives downed teammates. In runtime, `KeyE` (`input.ts:997-999, 1292-1297`) emits `{ t: 'use' }`, which on the server (`server/src/game/bansung/world.ts:1392-1405`) only interacts with weapon pedestals (`findNearestInteractablePedestal`). Co-op revive in `server/src/game/bansung/bot.ts:910-965` (`stepDownedAndRevive`) is purely automatic proximity channeling (`dx * dx + dy * dy <= BANSUNG_REVIVE_RADIUS^2`) when living allies stand inside the circle (as `Rules.tsx:166` correctly describes in the following bullet).

### [MINOR] Co-op Victory Pot Split Copy Mismatch (`Lobby.tsx`, `Rules.tsx`)
- **Files**: `client/src/components/Lobby.tsx:411, 826`, `client/src/components/Rules.tsx:166`
- **Issue**: All three VN copy blocks state thắng trận chia `"70% cho người sống sót + 30% MVP"`.
- **Actual Runtime** (`server/src/game/game.ts:1869-1891`): `Math.floor(this.pot * 0.7)` (70%) is split equally across `baseTargets` (survivors, or all `ranked` active humans if none survived), while the remaining ~30% (`perfPool = this.pot - allocated`) is distributed **proportionally by score (`scoreOf(p.id)`) among all finishing human players (`ranked`)**, with only rounding remainder (`rem`) added to `topId` (`this.winnerId ?? ranked[0].id`).

### [MINOR] Production `closeBundle` Copies Non-Allowlisted Raw Metadata JSONs (`vite.config.ts`)
- **Files**: `client/vite.config.ts:170-174, 198-208`
- **Issue**: `databaseBanSungPlugin` enforces `failClosed: true` and `isAllowedJson: (relPath) => relPath === 'manifest.json' || relPath.startsWith('normalized/')` in Vite dev (`configureServer`) and preview (`configurePreviewServer`), matching `guardBanSungStaticRequest` in `server/src/app.module.ts:45-105`. All client runtime JSON fetches target `manifest.json` (verified in `client/src/bansung/sprites.ts:751-788` and `client/src/bansung/sound.ts`). However, `closeBundle()` (`vite.config.ts:170-174`) executes `cpSync(opts.srcDir, opts.distDir, { recursive: true })`, copying raw JSON metadata (`sources.json`, `sprites/**/meta-*.json`, `audio/**/meta-*.json` in `database-ban-sung/`) into `client/dist/database-ban-sung/`. Behind NestJS `AppModule` (`AppModule:172-194`), `BanSungStaticGuard` and `ServeStaticModule` `exclude` still block those files, but if `client/dist` is ever served standalone on a static CDN/Nginx, those non-allowlisted JSONs would be present in the bundle output.
