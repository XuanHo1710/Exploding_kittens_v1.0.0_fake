## Scope

Cross-check the `4224x2688` (`88x56` @ `48px`) large arena layout, `12` enemy gates, `5` weapon pedestals, `3` biomes (`desert`, `crypt`, `cyber`), and `512x512` terrain chunk cache across:

- Shared definitions & generators: `shared/src/bansung.ts`, `shared/src/bansung/types.ts`, `shared/src/bansung/maps.ts`
- Server map/spatial/runtime consumers: `server/src/game/bansung/map.ts`, `server/src/game/bansung/spatial.ts`, `server/src/game/bansung/world.ts`, `server/src/game/bansung/director.ts`, `server/src/game/bansung/pickups.ts`, `server/src/game/game.ts`

- Asset manifest & tests: `database-ban-sung/manifest.json`, `server/test/bansung-physics.test.cjs`

## Cross-Check Findings

- **BLOCKER**: None.

- **[MAJOR] `5` Map Pedestals (`arena.pedestals` & `PEDESTAL_WEAPON_POOLS`) Unused at Match Start and Biome Pool Ignored**
  - `shared/src/bansung/maps.ts` (`lines 236-248`) defines `PEDESTAL_ANCHORS` (`West Shrine (1056, 1368)`, `East Shrine (3168, 1368)`, `North Shrine (2112, 528)`, `South-West Shrine (1296, 2088)`, `South-East Shrine (2928, 2088)`) with `pickupKind: 'weapon'`, `radius: 36`, `spriteId: 'pedestal'`, and biome-curated `PEDESTAL_WEAPON_POOLS`, which `server/src/game/bansung/map.ts` preserves on `arena.pedestals`.
  - At match start (`t = 0`), `BansungWorld` (`server/src/game/bansung/world.ts`) constructs `arena` with `arena.pedestals.length === 5` while `pickupMgr.pickupList` is empty (`0` spawned pedestals).
  - In `server/src/game/bansung/director.ts` (`buildSurvivalPedestalDrops`, `lines 2042-2072`), `ctx.arena?.pedestals` (`shrines`) is only indexed for `i >= 1` (multi-drop cycles after `i === 0` drops at `ctx.bossPos`) or when `ctx.bossPos` is missing, and neither `world.ts` nor `director.ts` passes `shrine.weaponPool` into `pickupMgr.spawnWeaponPedestal(..., { allowedWeapons })`.
  - Client `getOrBakeTerrainChunk` (`client/src/bansung/render.ts`) draws the boss arena pad and `12` enemy spawn gates into baked terrain chunks, with no floor shrine pad/emblem at the `5` `PEDESTAL_ANCHORS`.

- **[MINOR] `render.ts` `getObstacleLabelKind` Reads `kindIdx`/`propKind` Instead of `StaticObstacleBox.propKindIdx`**
  - `server/src/game/bansung/world.ts` / `server/src/game/game.ts` streams packed obstacles (`5` fields/box, `w.staticObstacles()`) which `client/src/bansung/store.ts` decodes into `StaticObstacleBox { x, y, w, h, propKindIdx }` (`lines 237-243`, `598-611`).
  - `getObstacleLabelKind` (`client/src/bansung/render.ts`, `lines 1310-1319`) reads `(obs as ...).kindIdx` and `.propKind` (both `undefined` on decoded boxes) instead of `obs.propKindIdx`, falling back to `desert ? (w <= 56 && h <= 56 ? 'rock' : 'pillar') : 'pillar'`.
  - Downstream in `drawStaticObstacle25D` (`render.ts`, `line 1346`), any `<= 56x56` `cyber` block (`mapBlockToPropKind` -> `'pillar'`) hits `['server', 'prop_server', 'pillar', 'prop_pillar']`, rendering server rack sprites instead of pillar sprites on `1x1` cyber conduit pillars.

- **[MINOR] Chunk Cache Rebake Checks Miss Trim/Decor Sprites; Stale Header JSDoc**
  - `getOrBakeTerrainChunk` (`client/src/bansung/render.ts`, `lines 1100-1117`) checks `isSpriteLoaded('tile_${biome}_floor')` (`existing.hasTileSprite`) and `isSpriteLoaded('tile_${biome}_wall')` (`existing.hasWallSprite`) to trigger rebake, omitting `tile_${biome}_trim` and `decor_*` sprites. Chunks baked after floor/wall load but before trim/decor finish loading retain procedural fallback trim/decor until evicted.
  - Header comment in `client/src/bansung/render.ts` (`line 8`) still documents `8 enemy spawn gates` while the renderer draws all `12` gates (`lines 1255-1270`).

- **[MINOR] `MAX_TERRAIN_CHUNKS = 32` Risks LRU Eviction Thrash When Zoomed Out on Wide Viewports**
  - A `4224x2688` arena spans `9 x 6 = 54` chunks at `RENDER_CFG.CHUNK_SIZE = 512` (`client/src/bansung/render.ts`, `lines 167-168`).
  - With `MAX_TERRAIN_CHUNKS = 32`, `CULL_PAD_PX = 160`, and zoom-out allowed down to `BANSUNG_ZOOM_MIN = 0.75` in `store.ts` (`>= 0.5` clamp at `render.ts:3397`), wide viewports (e.g., `2560x1440` at `1.0` zoom or `1920x1080` at `0.75` zoom) can span `> 32` visible chunks in a single frame, causing per-frame LRU eviction and rebake churn. (Note also `BansungBoard.tsx:239` omits `arenaSeed` from `sessionKey`, though chunk keys `${biome}:${seed}:${mapW}x${mapH}:${cx},${cy}` avoid cross-seed cache collisions and `clearBansungRenderCaches()` runs on session changes/unmount at `lines 249, 269`.)

## Verified Invariants

1. **Arena Dimensions & Playable Bounds**: Exact `48px` tile, `88x56` grid, `4224x2688` total dimensions, `BANSUNG_ARENA_CX = 2112`, `BANSUNG_ARENA_CY = 1368`, and `BANSUNG_PLAYABLE_BOUNDS = { x0: 48, y0: 96, x1: 4176, y1: 2640 }` (North wall 2 tiles / `96px`; W/E/S walls 1 tile / `48px`) match across `shared/src/bansung/types.ts`, `shared/src/bansung.ts`, `shared/src/bansung/maps.ts`, `server/src/game/bansung/map.ts`, `client/src/bansung/store.ts`, `client/src/bansung/render.ts`, and `client/src/components/BansungBoard.tsx`.
2. **`12` Enemy Gates & `8` Player Spawns**: All `12` gates in `BANSUNG_ENEMY_GATES` (4 cardinal + 4 corner + 4 mid-quadrant) and all `8` player spawns are unblocked across all `3` biomes for seeds `0..200`; `render.ts` (`lines 1255-1270`) draws all `12` gates with `-64..size+64` chunk-bleed tolerance (covering chunk-boundary gate `x = 3072` and center boss pad straddling `cx = 3/4`).
3. **`3` Biomes & Procedural Layout Determinism**:
   - Deterministic Node verification on compiled output across seeds `0..1000` confirmed `0` interior block overlaps in all 3 biomes (`desert`: 30 blocks = 4 perimeter + 26 interior, `minNonFlushGap=281`, `minWallGap=216`, `minBossDist=504`; `crypt`: 26 blocks = 4 + 22 interior, `minNonFlushGap=240`, `minWallGap=384`, `minBossDist=406`; `cyber`: 28 blocks = 4 + 24 interior, `minNonFlushGap=379`, `minWallGap=384`, `minBossDist=480`).
   - Across seeds `0..200`, all 3 biomes generate `48` solid + `24` decor = `72` props with `0` obstructions on `bossPad`, `8` player spawns, `12` enemy gates, and `5` pedestals.
   - Server `ObstacleGrid` initializes `66 x 42` cells (`ceil(4224/64) x ceil(2688/64)`) in `server/src/game/bansung/spatial.ts`, matching the server `desert` `BansungWorld` test instance (`26` obstacles packed as `staticObstacles().length === 130` ints).
4. **Asset Manifest Alignment**: All `47` terrain/block/prop/pedestal sprite keys referenced by `client/src/bansung/render.ts` exist in `database-ban-sung/manifest.json` (`missing: []`).
5. **Existing Physics/Map Test Suite**: `node --test server/test/bansung-physics.test.cjs` executed cleanly (`16` passed, `0` failed, `0` skipped, including `T01.1` `3-biome arena layouts (4224x2688)` and `T01.2` `ObstacleGrid` 64px spatial indexing).

## Verdict

**FAIL** — Core `4224x2688` geometry, `12` enemy gates, `3` biome cover generators, `66x42` `ObstacleGrid`, and sprite keys align across shared/server/client, **but** the `5` `PEDESTAL_ANCHORS` and `PEDESTAL_WEAPON_POOLS` (`arena.pedestals`) have a **MAJOR** runtime/visual wiring gap (not spawned at match start, `weaponPool` never forwarded to `spawnWeaponPedestal`, and no floor shrine rendering on terrain chunks), alongside **3 MINOR** client obstacle-kind / chunk-cache issues.
