## Cross-Check Findings

### 1. [severity: BLOCKER] Shared `pr`/`pk` dirty flags cleared inside `frameFor()`, breaking multi-player and spectator sync
- **Locations:** `server/src/game/bansung/world.ts:1229-1231, 3958-3963, 4007-4018`; `server/src/game/bansung/pickups.ts:2093-2097`; `server/src/game/game.ts:1919-1930`; `server/src/game/rooms.service.ts:74-77`; `client/src/bansung/store.ts:1123-1135`
- **Root Cause:** `Game.sendBansungFrames()` iterates sequentially over every connected player (`w.frameFor(p.id)`) and spectator (`w.frameFor(undefined)`), then calls `w.clearPendingFx()` once at the end (`game.ts:1929`). However, `clearPendingFx()` only zeroes `this.fx.length = 0`. Meanwhile `frameFor()` resets `this.arena.propsDirty = false` (`world.ts:4014`), updates `this.hadGadgetPropsLastTick = hasGadgetProps` (`world.ts:4016`), and calls `this.pickupMgr.packPickupsIfChanged(isInitial)` (`world.ts:4018`), which immediately sets `this.pkDirtyFlag = false` (`pickups.ts:2095`).
- **Secondary Defects in Same Path:**
  - Spectators pass `viewerId = undefined`, so `isInitial` (`world.ts:3960`) is always `false` and `full` (`L4046`) is omitted; on tick 0 (`startBansung()`), human players run first and wipe `propsDirty`/`pkDirtyFlag`, so spectators receive `{}` without initial `pr`/`pk`.
  - `Game.setConnected()` (`game.ts:451-480`) never removes a reconnecting player from `world.viewerInitialized` (`world.ts:759`), so reconnecting/reloading clients miss `full: true` and `pr`/`pk` recovery.
  - `RoomsService.hooks.bansungFrame` (`rooms.service.ts:76`) emits via `.volatile.emit`, so dropping a single delta frame loses one-shot `pr`/`pk` changes until the next prop/pickup mutation.
- **Observed Reproduction (`PROBE1` / `PROBE1B`):**
  - Tick 0 (`p0`, `p1`, spectator): `p0={full:true, prLen:240, pkLen:0}`, `p1={full:true, prLen:240, pkLen:0}`, spectator=`{}`.
  - Dirty tick (`propsDirty=true` + 1 spawned `energy_orb`): `p0={prLen:240, pkLen:5}`, `p1={}`, spectator=`{}`.
  - Turret despawn tick (`deployables.length = 0`): `p0={p0Pr:240}`, `p1={}` (`p1` retains ghost deployable in `prevSnap.props`).

### 2. [severity: BLOCKER] Downlink `bansung:frame` rate breaches the `< 12 KB/s` (`<= 400 B/f`) budget across both `test 2c` per-player JSON (`22.12 KB/s`) and real Survival combat (`79.38–133.93 KB/s`)
- **Locations:** `specs/004-ban-sung-coop/design/d47-perf-net-budget.md:7, 19-21, 46-57`; `server/src/game/game.gateway.ts:34`; `server/src/game/bansung/world.ts:3901-3955, 4007-4048`; `server/test/bansung-net-security.test.cjs:666-740`
- **Root Cause:**
  1. `d47` budgeted `< 12 KB/s` using a `DataView` binary codec with spawn-once projectiles and keyframe + `int8`-delta enemies. The implementation sends JSON `BansungFrame` (`shared/src/bansung/types.ts:520-542`) over Socket.IO with default `@WebSocketGateway({ cors: { origin: true } })` (`game.gateway.ts:34`, `perMessageDeflate` not enabled).
  2. `pr` (`packBreakableProps` + `packGadgetProps`) and `pk` (`packPickupsIfChanged`) are **not** viewport-culled across the `4224x2688` arena. While any deployable (`turret`/`mine`) is active (`hasGadgetProps`, `world.ts:4007-4009`), all arena destructibles (`905 B/f` = `~26.5 KB/s`) re-transmit every tick; magnetized `energy_orb` pickups move continuously (`86/90` ticks, `322 B/f` = `~9.4 KB/s`).
  3. `buildPrivateFor()` (`world.ts:3901-3955`) resends full JSON `me` every tick (`~436-445 B/f` baseline), and while `gachaChoices` is open (`GACHA_CHOICE_TIMEOUT_MS = 14_000`, `world.ts:499`) embeds 3 bilingual `BansungGachaCard` objects (`+955 B/f` -> `me = 1476 B/f` = `43.2 KB/s`), plus `srv` (`BansungSurvivalClock` JSON object, `112 B/f` = `~3.3 KB/s`).
  4. `test 2c` (`bansung-net-security.test.cjs:666-740`) passes only because `p0` is isolated with 0 visible mobs/bullets/pickups/FX and assertions check `< 12 KB/s` solely on spectator `pubJson` (without `me`) and `zlib.deflateRawSync(p0Json)` rather than actual per-player uncompressed Socket.IO JSON.
- **Observed Measurements (`90` ticks @ `30 Hz`):**
  - `TEST2C_EXACT` (`test 2c` fixture): spectator raw `9.14 KB/s`, **`p0` raw JSON `22.12 KB/s`**, `p0` deflate `11.43 KB/s`.
  - `LEVEL_UP_GACHA` (`0` mobs, `0` bullets, `0` pickups, `gachaChoices` open): `1685 B/f` = **`49.37 KB/s` raw** (`26.13 KB/s` deflate).
  - `SURVIVAL_BASE` (4 heroes `knight/mascot/ranger/pyro`, 44 nearby mobs, 24 `energy_orb` pickups): `p0` **`79.38 KB/s` raw** (`35.65 KB/s` deflate, max `3889 B/f`); avg fields `e=1075`, `b=481`, `me=445`, `pk=322`, `p=130`, `srv=112`, `fx=41`, `pr=20`.
  - `SURVIVAL_FULL` (same + `gachaChoices` open + active `turret`): `p0` **`133.93 KB/s` raw** (`62.49 KB/s` deflate, max `5081 B/f`); avg fields `me=1479`, `e=1084`, `pr=905` (`90/90` ticks), `b=454`, `pk=263` (`74/90` ticks), `srv=112`, `p=131`, `fx=52`.

### 3. [severity: MAJOR] Match-end `finalizeResult()` invokes `syncBansung()` -> `sendBansungFrames()` before `rebuildCullingCache()`, emitting duplicate end-tick frames with stale culling
- **Locations:** `server/src/game/bansung/world.ts:1488-1495, 2705-2709, 2786-2818`; `server/src/game/game.ts:1845-1917`
- **Details:** Inside `step()`, `stepWaveDirector()` (`L1488`) or `checkMatchEnd()` (`L1491`) invokes `finalizeResult()` -> `this.hooks.changed()` (`L2816`) **before** `rebuildStaticAndPropViews()` (`L1492`), `rebuildCullingCache()` (`L1493`), and `this.hooks.tick()` (`L1494`). `Game.syncBansung()` (`game.ts:1915`) immediately calls `this.sendBansungFrames()`, broadcasting a frame built from the previous tick's culling buckets and clearing `fx` / `propsDirty` / `pkDirtyFlag`; `step()` then finishes with `this.hooks.tick()`, sending a second frame for the same `tickNo` without `fx`.
- **Observed (`PROBE3B`, 2-player `Game`):** `tickCounts` recorded `t=0: 2`, `t=1: 2`, and end-tick **`t=2: 4`** (`2` frames per connected player on the same tick).

### 4. [severity: MAJOR] Free-play co-op settlement (`bet = 0`) credits `acc.wins++` only to MVP (`game.winner()`), excluding co-op teammates
- **Locations:** `server/src/game/game.ts:1862-1892, 2170-2176`; `server/src/game/rooms.service.ts:294-336`; `server/src/store/accounts.service.ts:231-244, 284-290`
- **Details:** On victory, `syncBansung()` populates `this.winnerIds = ranked.map((p) => p.id)` and `this.winnerId = mvpId ?? ranked[0]?.id`, but populates `this.payouts` only when `this.pot > 0`. - **Details:**
