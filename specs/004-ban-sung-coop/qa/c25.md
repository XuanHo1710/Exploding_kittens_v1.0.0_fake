## Cross-Check Findings

1. **[MAJOR] `FX_STATUS` listener reads world X (`ev.d`) instead of `statusKind` (`ev.b`), disabling reload/level-up/gacha/downed HUD feedback**
   - Server emits 6-field `FX_STATUS` tuples `[5, playerIdx, statusKind, extraArg, Math.round(x), Math.round(y)]`: `world.ts:2871-2878` (`BANSUNG_STATUS_LEVELUP = 7`), `world.ts:2963-2970` (`BANSUNG_STATUS_GACHA = 8`), `weapons.ts:938-945` (`BANSUNG_STATUS_RELOAD_PERFECT = 2`), and `bot.ts:896-903` (`BANSUNG_STATUS_DOWNED = 3`).
   - `client/src/bansung/store.ts:613-623` (`decodeFxArray`) maps those indices to `{ type, a: playerIdx, b: statusKind, c: extraArg, d: x, e: y }`, which `sound.ts:1838-1853` and `render.ts:2960` correctly consume via `b`.
   - `HudBars.tsx:2599-2611` assigns `const statusKind = ev.d;` (the world X coordinate, always `>= 48` inside playable bounds), and `BansungBoard.tsx:804-817` omits `reloadPerfectedAt` and `dryFireAt` props. Consequently, `fxReloadPerfectedAt` (`FAST RELOAD!` flash), `fxDownedAt` (`data-downed-at`), and `fxLevelUpAt` (`.bs-lv-badge--flash` pulse on level-up / Gacha selection) never fire at runtime.

2. **[MAJOR] Active Reload `sweetSpot` `[0..100]` vs `[0..1]` scale mismatch misleads players into jamming + duplicate reload strip mounted**
   - `server/src/game/bansung/world.ts:3923-3929` (`buildPrivateFor`) packs `sweetSpot: [Math.round(reload.sweetMinU * 100), Math.round(reload.sweetMaxU * 100)]` (e.g. `[48, 64]`), and `client/src/bansung/store.ts:452-495` (`normalizePrivateSlice`) forwards `...raw` without rescaling `sweetSpot` back to `[0..1]`.
   - `HudBars.tsx:1146-1147` (`ActiveReloadBar`) clamps `sweetSpot?.[0]` to `[BANSUNG_RELOAD_LOCKOUT_U, 0.92]` and `sweetSpot?.[1]` to `[minU + 0.04, 0.98]`, turning `[48, 64]` into `[0.92, 0.98]`. Every server-driven reload renders the green sweet-spot bar at `92%–98%` instead of `48%–64%`, causing `[R]` presses inside the visual green zone to jam in `server/src/game/bansung/weapons.ts:931`.
   - Meanwhile, `BansungBoard.tsx:820-827` mounts `<HotbarShop ... showGachaModal={!ended} />` without `showReloadBar={false}` (`HotbarShop.tsx:2246` defaults to `true`), rendering a duplicate `<ActiveReloadStrip>` (`HotbarShop.tsx:2417-2423`) whose unclamped `me.sweetSpot?.[0]` (`HotbarShop.tsx:1449-1450`) overflows at `left: 4800%; width: 1600%` (and `render.ts:3183-3189` similarly multiplies `spot[0] * bw`).

3. **[MAJOR] `SquadStrip` ally `maxHp`/`maxShield` omits `HERO_STAT_SCALE = 10` (and Gacha max boosts), keeping ally bars stuck at `100%`**
   - `shared/src/bansung/heroes.ts:412-413,446-447` stores unscaled base stats (`mascot`: `hp: 6, shield: 5`; `ranger`: `hp: 5, shield: 4`), whereas `server/src/game/bansung/world.ts:472,863-864` multiplies them by `HERO_STAT_SCALE = 10` (`60` HP / `50` shield for mascot, plus `skill_hp` Gacha upgrades).
   - `world.ts:3844-3884` (`packAllPlayers`, `BANSUNG_PLAYER_FIELDS = 12`) broadcasts teammates' current `hp` and `shield` (`frame.p[+4/+5]`) without `maxHp`/`maxShield`.
   - `HudBars.tsx:1223-1224` (`SquadStrip`) computes `const maxHp = Math.max(hero.hp, ally.hp);` and `const maxSh = Math.max(hero.shield, ally.shield, 1);`. For any ally with `hp >= 6` (or `shield >= 5`), `Math.max` evaluates to the current value itself, locking ally HP/SH bars at `100%` width down to `<10%` of base HP. The same unscaled `hero.hp` / `hero.shield` fallback appears in `TopLeftHud` (`HudBars.tsx:1315-1318`) and `LowHpVignette` (`HudBars.tsx:2498`) if `me` is absent.

4. **[MINOR] Minimap pickup renderer classifies `armor_plate` (`kindIdx === 4`) as gold Weapon Pedestal diamonds**
   - `server/src/game/bansung/pickups.ts:2083` packs `BANSUNG_PICKUPS[p.kind].kindIdx` (`0..10` aligned with `BANSUNG_PICKUP_KINDS`), where `4` is `armor_plate`, `6` is `gem_coin`, `7` is `weapon_pedestal`, and `8..10` are `xp_orb_s/m/l` (`shared/src/bansung/enemies.ts:2255-2353`).
   - `encodePickupSubVal` (`pickups.ts:498-507`) sets `subVal = stackBits | (expiringFlag << 12)` (`>= 1` whenever `stack >= 1`).
   - `HudBars.tsx:1714` evaluates `const isPedestal = kindName === 'weapon_pedestal' || (pk.kindIdx === 4 && pk.subId > 0);`, which matches every `armor_plate` (`kindIdx === 4, subId >= 1`) as a gold weapon pedestal diamond instead of a green pickup dot, while `isCoarseXp` (`HudBars.tsx:1713`: `!kindName && BANSUNG_PICKUP_IDS[pk.kindIdx] === 'xp'`) is unreachable dead code because `BANSUNG_PICKUP_KINDS` defines all indices `0..10`. (`HotbarShop.tsx:163,935-940` correctly checks `WEAPON_PEDESTAL_KIND_IDX === 7`.)

5. **[MINOR] Mobile/narrow (`<= 760px`) top-center Survival Timeline & Boss Bar overlap `TopLeftHud`/`TopRightUtility` and `.bs-loading-pill`**
   - At `<= 760px` (e.g. `375px` portrait), `.bs-boss-bar` (`width: min(320px, 56vw)` in `bansung.css:834`, `HudBars.tsx:923`) and `.bs-survival-strip` (`width: min(320px, 52vw)` in `bansung.css:1107`, `54vw` in `HudBars.tsx:924`) remain centered at `top: 8px`, horizontally colliding with `.bs-hud-tl` (`34px` portrait + `128px` bars + padding ≈ `176px+` from left) and `.bs-hud-tr` (`114px` minimap + padding ≈ `126px` from right).
   - `.bs-loading-pill` (`bansung.css:103-108`, `top: calc(max(12px, env(safe-area-inset-top)) + 64px)`) overlaps `.bs-survival-strip--under-boss` (`bansung.css:967-969`) and `.bs-wave-banner` (`HudBars.tsx:726-728`) during initial sprite preload (`BansungBoard.tsx:677`).

6. **[MINOR] Split `M` minimap hotkey handling and unused legacy `renderBansungRadar` in `render.ts`**
   - `client/src/bansung/input.ts:1257-1262` dispatches `this.onUiAction?.('minimap')` on `M`, which `BansungBoard.tsx:364-376` ignores; `MinimapHud` (`HudBars.tsx:1882-1892`) registers its own `window` `keydown` listener (`m`/`M`) without suppressing mode toggles while `guideOpen`/`leaveOpen`/`ended` modals are open.
   - `client/src/bansung/render.ts:4360-4568` retains an unused `renderBansungRadar` implementation with diverging styling (missing `BANSUNG_ENEMY_GATES` and `RADAR` dashed circle).

7. **[MINOR] Portrait path divergence from `manifest.json` and stale `2112:1344` / `d45` comments**
   - `HeroPortrait` (`HudBars.tsx:1055`) loads `/database-ban-sung/sprites/heroes/${hero.id}_idle.png` (`192x48` 4-frame sheet cropped to frame 0 via `.bs-hero-portrait img` `object-fit: cover; object-position: left center` at `HudBars.tsx:373-380`) rather than the dedicated `32x32` portraits in `database-ban-sung/manifest.json` (`normalized/ui/ui_portrait_{mascot,ranger,pyro,knight}.png`); both paths are served cleanly by `BanSungStaticGuard` (`server/src/app.module.ts:45-160`) and `databaseBanSungPlugin` (`client/vite.config.ts:198-208`).
   - `HudBars.tsx:92` JSDoc cites `2112:1344` instead of `4224:2688` (same `11:7` ratio).

## Verdict: FAIL
Three **MAJOR** runtime HUD bugs require fixes before passing: `FX_STATUS` handler reading `ev.d` (world X) instead of `ev.b` (`statusKind`), `ActiveReloadBar` (`HudBars.tsx`) receiving unnormalized `[0..100]` `sweetSpot` tuples while a duplicate `HotbarShop` reload strip stays mounted, and `SquadStrip` using unscaled `hero.hp`/`hero.shield` without `HERO_STAT_SCALE = 10` or broadcast teammate max stats.
