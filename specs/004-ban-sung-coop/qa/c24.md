## Cross-Check Findings

1. **[MINOR] `ENEMY_STATE_DEAD = 7` mismatches wire `BANSUNG_STATE_DEAD = 6`**
   - `client/src/bansung/input.ts` (L76, L304, L1750) checks `enemy.state === ENEMY_STATE_DEAD` with local constant `7` (matching internal AI enum `BANSUNG_ENEMY_STATE_INDEX.dead` in `shared/src/bansung/enemies.ts:45`).
   - On the wire (`BansungFrame.e`), `server/src/game/bansung/mobs.ts:2868` (`mapAiStateToWireByte`), `boss-sand.ts:163`, `boss-colossus.ts:2203`, and `boss-overlord.ts:2175` all pack `BANSUNG_STATE_DEAD = 6` (`shared/src/bansung/types.ts:122`), matching `client/src/bansung/render.ts:4468`.
   - Impact is mitigated in live snapshots because `world.ts:3695` skips `!mob.alive || mob.hp <= 0` and `mobs.ts:2893` packs `hpPct = 0` when dead, so `enemy.hpPct <= 0` still filters dead units unless a dead tuple with `state === 6` and non-zero `hpPct` is ever sent.

2. **[MINOR] `findAutoAimTarget` treats wire `hpPct === 1` (1% HP) as 100% HP**
   - `server/src/game/bansung/mobs.ts:2893` and `world.ts:3712,3753,3777` encode enemy/boss `hpPct` as integers in `[0..100]`.
   - `client/src/bansung/input.ts:312` computes `const normHp = enemy.hpPct > 1 ? enemy.hpPct / 100 : enemy.hpPct;`, so an enemy at exactly `1%` HP (`hpPct === 1`) evaluates to `normHp = 1` instead of `0.01` and misses the `-80` low-HP priority bonus (`normHp < 0.25`).

3. **[MINOR] `[1/2/3]` Gacha hotkey intercept lacks spectate/modal-block guard and sub-tick repeat lock**
   - `client/src/bansung/input.ts:1264-1274` intercepts `1/2/3` (`Digit1..3`, `Numpad1..3`, `'1'..'3'`) whenever `getActiveGachaChoicesLen() > 0` before checking `!this.alive || this.downed || e.repeat`.
   - When dead/spectating (`HotbarShop.tsx:2399` hides `GachaDraftModal` via `!spectating`) or while `guideOpen` / `leaveOpen` / `ended` is active in `BansungBoard.tsx`, `input.ts` can still dispatch `{ t: 'gacha', pick }` blindly if stale `me.gachaChoices` are present.
   - `HotbarShop.tsx:2116` locks duplicate pointer clicks via `pickedIdx`, whereas `input.ts` does not track a local submission guard between keypresses arriving within the same ~33ms tick when `gachaPending >= 2`.

4. **[MINOR] Mobile auto-aim lock diamond in `render.ts` is suppressed when `touchUi` is true**
   - `client/src/bansung/render.ts:2707-2720` draws the pulsing red mobile auto-aim diamond (`iv.autoAimTargetId`, `autoAimTargetX`, `autoAimTargetY`) inside `drawAimReticle`, which is skipped when `o.showCrosshair === false` (`render.ts:4224`).
   - `client/src/components/BansungBoard.tsx:549` passes `showCrosshair: activeControls && !localDowned && !iv.touchUi && !uiBlockRef.current`, suppressing the canvas lock diamond in touch mode (though the HUD stick tag still displays `LOCK` at `BansungBoard.tsx:514-520`).

5. **[MINOR] Touch sticks are not reset when draft overlays hide `.bs-touch-layer` (`display: none`)**
   - `BansungBoard.tsx:690` sets `display: none` on `.bs-touch-layer` whenever `hasDraftOverlay` (`me?.gachaChoices?.length || me?.perkChoices?.length`) is true, while `BansungBoard.tsx:305-309` only calls `bansungInput.resetAll()` for `[ended, guideOpen, leaveOpen]`.
   - `input.ts:687` listens to `pointerup` on `window` (but not `pointercancel`), so a thumb held on `.bs-touch-zone--move` or `--aim` when the Gacha modal pops up keeps the touch slot active until release.
   - Separately, on standard-height screens (`rAim = 58`), `input.ts:1466` switches from auto-aim to manual aim at `dist >= 10px` (`0.1724`), while `store.ts:1317` (`setStickAim`) activates local aim override at `mag > 0.18` (`10.44px`), leaving a negligible `0.44px` band before local preview rotates.
