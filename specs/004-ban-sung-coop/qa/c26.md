## Cross-Check Findings

### 1. [severity: MAJOR] Sparse `weaponState.slots` vs. compacted `me.slots` / uncompacted `weaponTiers` & `slotIdx` breaks hotbar slot mapping and hides melee slot `[5]`
- **Where**:
  - `server/src/game/bansung/weapons.ts:630-636` (`createHeroWeaponState`) vs. `server/src/game/bansung/weapons.ts:1052-1068` (`buildWeaponSlotsSnapshot`)
  - `server/src/game/bansung/world.ts:3903-3917` (`buildPrivateFor`)
  - `shared/src/bansung/weapons.ts:2957` (`buildWeaponUpgradeCard`)
  - `client/src/components/bansung/HotbarShop.tsx:1441, 1996, 2437-2464`
- **Detail**:
  - `createHeroWeaponState` allocates 5 slots (`BANSUNG_MAX_WEAPON_SLOTS = 5`): `[sidearm, starter, null, null, 'crescent_blade']`.
  - `buildWeaponSlotsSnapshot` skips `null` entries (`if (!s) continue`), compacting the initial loadout into 3 elements: `me.slots[0]` = sidearm (server `0`), `me.slots[1]` = starter (server `1`), `me.slots[2]` = `crescent_blade` (server `4`), `me.slots[3]` = `undefined`, `me.slots[4]` = `undefined`.
  - Meanwhile, `world.ts:3904` emits `weaponTiers = p.weaponState.slots.map((s) => (s ? s.tier : 1))` **without** skipping `null` (length 5), `world.ts:3917` emits `slotIdx: p.weaponState.activeSlot` (`0..4`), and `buildWeaponUpgradeCard` emits `card.slotIdx` in `0..4`.
  - `HotbarShop.tsx:2437-2464` renders only slots `0, 1, 2` (`WeaponHotbarSlot`) and slot `3` (`SupplyHotbarSlot` fallback to consumable `[5]`) with no slot `4` (`[5]`) weapon renderer.
- **Impact**:
  - On default 3-weapon loadouts, melee (`crescent_blade`, server slot `4`) appears in hotbar key `[3]`; clicking it dispatches `selectSlot(2)` (empty server slot `2`, rejected by `switchHeroWeaponSlot`), while pressing key `5` (`slotIdx = 4`) leaves **no** hotbar slot highlighted and causes `ActiveReloadStrip` (`me.slots[me.slotIdx]` at `HotbarShop.tsx:1441`) to read `undefined`.
  - `GachaDraftCard` (`HotbarShop.tsx:1996`) displays `Ô [${card.slotIdx + 1}]` (e.g. `Ô [5]`), mismatching the visual hotbar slot `[3]`.
  - `me.weaponTiers[2]` comes from empty server slot `2` (`tier = 1`) rather than `crescent_blade`'s tier at `me.weaponTiers[4]` (masked only because `buildWeaponSlotsSnapshot` populates `slot.tier` first in `resolveSlotWeaponTier`, `HotbarShop.tsx:1110-1112`).

### 2. [severity: MAJOR] `ActiveReloadStrip` treats `me.sweetSpot` (`0..100` integer %) as `0..1` normalized progress
- **Where**:
  - `server/src/game/bansung/world.ts:3923-3929` (`buildPrivateFor`)
  - `client/src/components/bansung/HotbarShop.tsx:1448-1467` (`ActiveReloadStrip`)
  - *(Related sibling: `client/src/components/bansung/HudBars.tsx:1146-1147`)*
- **Detail**:
  - Server encodes `sweetSpot: [Math.round(reload.sweetMinU * 100), Math.round(reload.sweetMaxU * 100)]` (e.g. `[48, 64]`).
  - `ActiveReloadStrip` compares normalized needle progress `u = clamp(1 - me.reloadMs / Math.max(1, me.reloadTotalMs), 0, 1)` (`0..1`) directly against `sweetMin = me.sweetSpot?.[0] ?? BANSUNG_RELOAD_SWEET_MIN` and `sweetMax = me.sweetSpot?.[1] ?? BANSUNG_RELOAD_SWEET_MAX`, and renders CSS `left: ${sweetMin * 100}%` and `width: ${Math.max(2, (sweetMax - sweetMin) * 100)}%`.
- **Impact**:
  - During reload when `me.sweetSpot` is sent, the sweet-spot band renders off-track (`left: 4800%`, `width: 1600%`) and `u >= sweetMin` (`[0..1] >= 48`) is always `false`, preventing `[R] HOÀN HẢO!` from appearing.

### 3. [severity: MAJOR] Missing `maxClip > 0` guard for melee weapons (`clip: -1, maxClip: 0`)
- **Where**:
  - `shared/src/bansung/weapons.ts:1732, 1783, 1834` (`magSize: 0` on melee weapons)
  - `server/src/game/bansung/weapons.ts:1062-1063` (`clip: spec.magSize > 0 ? s.ammoInMag : -1, maxClip: spec.magSize`)
  - `client/src/components/bansung/HotbarShop.tsx:1144-1149, 1164, 1215-1217, 1485-1504`
- **Detail**:
  - Unlike `client/src/components/BansungBoard.tsx:648` (`activeWeapon.maxClip > 0`) and `client/src/bansung/input.ts:884` (`slotInfo.maxClip > 0`), `WeaponHotbarSlot` (`HotbarShop.tsx:1145, 1215-1217`) formats `slot.clip/slot.maxClip` unconditionally and flags `slot.clip <= 0` as `bs-slot-ammo--empty`.
  - `ActiveReloadStrip` (`HotbarShop.tsx:1485-1504`) checks `if (activeSlot && activeSlot.clip <= 0)` without checking `activeSlot.maxClip > 0`.
- **Impact**:
  - Melee slots always render a red `-1/0` ammo badge/tooltip. Whenever a melee weapon resides at `me.slots[me.slotIdx]` (e.g. compacted `crescent_blade` at index `2` while `slotIdx === 2`), `ActiveReloadStrip` persistently shows `HẾT ĐẠN (...)` + `[R] NẠP ĐẠN`.

### 4. [severity: MINOR] `PedestalSwapPrompt` `hasFreeSlot` (`slots.length < 3`) disagrees with server `interactPedestal` & slot cap (`3` vs `5`)

  - `client/src/components/bansung/HotbarShop.tsx:1543-1545, 1626-1631` (`PedestalSwapPrompt`)

  - Server `interactPedestal` clamps `slotIdx` to `0..2` (`BANSUNG_MAX_WEAPON_SLOTS = 3` in `pickups.ts:110`) and unconditionally overwrites `hero.slots[slotIdx]` (active slot) rather than placing into an empty slot, while `world.ts:1401` calls `equipWeaponInSlot(player.weaponState, player.slotIdx, res.gainedWeapon)` using unclamped `player.slotIdx` (`0..4`).

### 5. [severity: MINOR] `GachaDraftModal` `+N hộp chờ` badge is off-by-one when server sends `gachaPending`

## Verdict: FAIL
- **Reason**: Three `MAJOR` UI/server desynchronizations (`me.slots` compaction vs. sparse `weaponTiers`/`slotIdx`/missing slot `[5]`, `sweetSpot` `0..100` vs. `0..1` scale mismatch in `ActiveReloadStrip`, and unguarded `-1/0` melee ammo/reload prompt) plus three `MINOR` UI/state inconsistencies (`PedestalSwapPrompt` `hasFreeSlot`, `gachaPending` `+N hộp chờ` off-by-one, and `[Q / 4]` tooltip mismatch).
