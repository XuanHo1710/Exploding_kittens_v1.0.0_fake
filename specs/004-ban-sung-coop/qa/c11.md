## Cross-Check Findings

### [MAJOR] F1 — Double-scaled `bossHpMult` (squared co-op & difficulty HP + leaked Classic `endlessTier`) across `director.ts` → `world.ts` → Boss constructors
- **Mismatch:**
  - `shared/src/bansung/enemies.ts` `getSurvivalScheduleState` (L1685–1688) already bakes co-op player count and difficulty into `bossHpMult`:
    `computeBossHpMult(n, difficulty, 0) * cycleMult * (bossSlotIdx > 0 ? 1 + 0.15 * bossSlotIdx : 1)`.
    In Classic `'waves'` mode, `director.ts` `beginNextWave` (L1333, L1383, L1402) likewise sets `this.bossHpMult = computeBossHpMult(nPlayers, difficulty, endlessTier)` and emits `out.spawnBoss.hpMult = this.bossHpMult` (or `* spec.miniBoss.hpMult`).
  - However, `BansungWorld.spawnWaveBoss` (`server/src/game/bansung/world.ts` L2719–2783) passes **both** `playerCount`, `difficulty`, `endlessTier` **and** `hpMult: spec.hpMult` to every boss constructor:
    - `createSandBeholderBoss` (`boss-sand.ts` L409–416, L459–463): `computeBossHpMult(playerCount, diffKey, endlessTier) * waveMult`.
    - `createDreadColossus` (`boss-colossus.ts` L1184–1200): `computeBossHpMult(playerCount, difficulty, endlessTier) * hpMult` (and Colossus `droneMaxHp` also multiplies `(1 + 0.45 * (clampedPlayers - 1)) * diffScale * endlessDroneMult * hpMult`).
    - `createOverlordBoss` (`boss-overlord.ts` L609–623): `(1 + coOpHpPerExtraPlayer * (nPlayers - 1)) * diffMul * (1 + endlessHpScale * endlessTier) * hpMult` (and `wpBaseHp` also multiplies `diffMul * (1 + 0.25 * endlessTier) * hpMult`).
  - Additionally, `world.ts` L2719 computes `endlessTier = Math.max(0, Math.floor((this.director.wave - BANSUNG_TOTAL_WAVES) / 10))` unconditionally from `this.director.wave`. In Survival mode (`this.director.wave = schedule.cycle * 4 + schedule.stageIdx + 1`, `director.ts` L1911), from Cycle 5 `boss_hunt` onward (`wave >= 23`), `endlessTier >= 1` stacks Classic Waves' `(1 + 0.35 * endlessTier)` multiplier on top of Survival's `cycleMult`.
- **Impact:**
  - In 1P Normal Cycle 0 (`computeBossHpMult = 1.0`), boss HP matches `1.0x`.
  - In 4P Hard Cycle 0 Stage 2 (`boss_hunt`), `computeBossHpMult(4, 'hard', 0) = 2.95 * 1.35 = 3.9825`, causing Beholder/Colossus to spawn at **`3.9825² = 15.86x` `baseHp`** (~4x intended HP inside a `110s` boss-hunt window); in 4P Hell/Insane (`d.bossHp = 1.75`), **`5.1625² = 26.65x` `baseHp`** (>5x intended HP), and **`34.65x`** on the 3rd boss (`bossSlotIdx = 2`). Classic `'waves'` co-op/hard+ bosses spawned via `BansungWorld` suffer the same squaring.
- **Why tests missed it:** `bansung-ai-waves.test.cjs` validates `WaveDirector.step()` outputs (`spawnBoss`) directly without spawning `boss_beholder`/`boss_colossus`/`boss_overlord` inside `BansungWorld`.

### [MINOR] F2 — `finalizeResult` & `PostGameModal` report `Đợt 0/10` in Survival mode (`world.ts` ↔ `PostGameModal.tsx`)
- **Mismatch:**
  - `director.ts` `stepSurvival` (L1854–2004) never increments `this.wavesCleared` (it remains `0`), while `this.wave` tracks `schedule.cycle * 4 + schedule.stageIdx + 1`.
  - `world.ts` `finalizeResult` (L2800–2812) unconditionally passes `wavesCleared: victory ? Math.max(this.director.wavesCleared, this.director.wave) : this.director.wavesCleared` and `totalWaves: this.config.endless ? Math.max(BANSUNG_TOTAL_WAVES, this.director.wave) : BANSUNG_TOTAL_WAVES` (`10`) to `buildBansungResult`. Because Survival matches end via defeat (`checkMatchEnd`, L2786–2798), `result.wavesCleared` is always `0` and `result.totalWaves` is `10`.
  - `client/src/components/bansung/PostGameModal.tsx` (L1108–1123, L1230–1233) renders `Đợt {wavesCleared}/{totalWaves}` (`Đợt 0/10`) without branching on Survival `cycle` / `stageIdx`.

### [MINOR] F3 — Overlapping `boss_hunt` kills can place `pedestalDrops` at a surviving boss's position (`world.ts` ↔ `director.ts`)
- **Mismatch:**
  - `BANSUNG_SURVIVAL_STAGES[2]` (`boss_hunt`) spawns a new boss every `110s` (`0s`, `110s`, `220s`), so multiple bosses can coexist in `this.activeBosses` if an earlier boss takes >110s to defeat.
  - `world.ts` `handleBossDeath` (L3369–3370) records `this.bossKillsThisTick += 1` and `this.lastBossDeathPos = { x, y }`, but `stepWaveDirector` (L2525–2545) evaluates `const aliveBoss = this.activeBosses.find(...)` and passes `bossPos: aliveBoss ? aliveBossPos : this.lastBossDeathPos` to `director.step(...)`.
  - If one boss dies while another boss remains alive, `bossPos` resolves to the **living** boss's coordinates rather than `this.lastBossDeathPos`, so `buildSurvivalPedestalDrops` (`director.ts` L2056–2064) spawns the weapon pedestal under the surviving boss instead of where the defeated boss died.

### [MINOR] F4 — `DirectorMobSpawn.scaleMult` & `SURVIVAL_EVOLVED_SCALE_MULT` (`1.16`) ignored by `mobs.ts` (`director.ts` ↔ `mobs.ts`)
- **Mismatch:**
  - `director.ts` computes `scaleMult` in `buildMobSpawn` (L2230, L2240, L2257) using `SURVIVAL_EVOLVED_SCALE_MULT = 1.16` (L147) and `ELITE_SCALE_MULT = 1.2` (L136), and checks spawn-point obstacle clearance in `spawnSurvivalBurst` (L2141–2145) with those multipliers.
  - `mobs.ts` `spawnMobFromDirector` (L821–843) never forwards `spawn.scaleMult` to `spawnMob` (L656–666), which independently sets `radius = Math.max(stats.radius + 2, Math.round(stats.radius * 1.15))` and `mass = stats.mass * 1.15` for `evolved` mobs and `1.0x` for elites. Because `1.15 <= 1.16` and `1.0 <= 1.2`, spawn clearance stays obstacle-free, leaving `scaleMult` as unconsumed payload metadata and creating a slight `1.15` vs `1.16` scale divergence.

### [MINOR] F5 — 0-indexed Survival cycle log vs 1-indexed client HUD/scoreboard (`world.ts` ↔ `HudBars.tsx` / `BansungBoard.tsx`)
- **Mismatch:** `world.ts` `stepWaveDirector` (L2584) pushes ``Vòng ${sc.cycle} — Giai đoạn ${sc.stageIdx + 1}: ${sc.vnName}`` (`Vòng 0` in Cycle 0, `Vòng 1` after the 20:00 wrap), whereas `HudBars.tsx` (L1425 `V{cycle + 1}`, L2153 `Vòng {cycle + 1}`) and `BansungBoard.tsx` (L906 `VÒNG ${(survivalClock?.cycle ?? 0) + 1}`) display 1-indexed `Vòng 1` in Cycle 0.

### [MINOR] F6 — `mobCap <= 72` exceeds viewport snapshot cap `FRAME_ENEMY_CAP = 64` (`enemies.ts` ↔ `world.ts`)
- **Mismatch:** `getSurvivalScheduleState` (`shared/src/bansung/enemies.ts` L1673–1676) permits up to `72` concurrent mobs (`mobCap = Math.min(72, ...)` — reached in 3P/4P `evolved_horde` or high cycles), while `BansungWorld.frameFor` (`world.ts` L481, L3993–3997) slices `tmpEnemyBucketOut` at `FRAME_ENEMY_CAP = 64` in insertion order without distance sorting, so up to 8 mobs inside a crowded viewport can be omitted from a viewer's `BansungFrame.e`.

## Verified Invariants
1. **20-Min Schedule & Stage Alignment (`shared/enemies.ts` ↔ `director.ts`):**
   - Constants & boundaries match cleanly: `BANSUNG_SURVIVAL_CYCLE_S = 1200`s, `BANSUNG_SURVIVAL_STAGE_S = 300`s, 4 contiguous stages (`0–300s swarm_light`, `300–600s heavy_brute`, `600–900s boss_hunt`, `900–1200s evolved_horde`), discrete second-based indexing (`elapsedS = Math.floor(safeMs / 1000)`), and `stageRemS = 300 - stageElapsedS`.
   - `stepSurvival` (`director.ts` L1854–2004) honors `BANSUNG_SURVIVAL_WARMUP_S = 3.0`s (`survivalElapsedMs` holds at `0` until warmup finishes so Stage 0 starts cleanly at `00:00`), updates `wave = schedule.cycle * 4 + schedule.stageIdx + 1`, emits `survivalStageChange` & `waveStart` once per stage/cycle transition, and emits `out.propRespawn` every `45`s (`SURVIVAL_PROP_RESPAWN_INTERVAL_S = 45`), wired to `this.arena.propsDirty = true` in `world.ts` (L2572–2574).
2. **Stage 2 (`boss_hunt`) Rotation & Stage 3 (`evolved_horde`) Flags (`enemies.ts` ↔ `director.ts` ↔ `mobs.ts` ↔ `client`):**
   - `boss_hunt` (`bossIntervalS: 110`, `bossRotation: ['boss_beholder', 'boss_colossus', 'boss_overlord']`) spawns all 3 bosses sequentially (`0s`, `110s`, `220s` into Stage 2; `bossSlotIdx` never hits `3` before `300s`), keyed by `${cycle}:${stageIdx}:${bossSlotIdx}` (`director.ts` L1956) so subsequent cycles re-trigger all 3 slots.
   - `evolved_horde` (`evolvedFlag: true`) sets `evolved: true` on `DirectorMobSpawn` (`director.ts` L2236, L2253), preserved on `MobState.evolved` (`mobs.ts` L765, L834) and serialized into `BANSUNG_EFLAG_EVOLVED` (`256`, `types.ts` L351; `mobs.ts` L2891), which is consumed by `client/src/bansung/render.ts` (L1998, L3079, L3848, L4470) and `HudBars.tsx` (L1749).
3. **Cycle+1 Wrap (`1200s` / `20:00`):**
   - Crossing `1200s` wraps `cycleSec -> 0`, `stageIdx -> 0 ('swarm_light')`, resets `evolvedFlag` to `false`, increments `cycle` (`0 -> 1`), scales `cycleMult = 1 + 0.55 * cycle`, tightens `burstCadenceS` (`Math.max(1.2, ...)`), caps `dmgMult <= 3.5` and `eliteChance <= 0.85`, adds `bonusArmor += cycle * 2` and `speedMult *= (1 + Math.min(0.25, 0.05 * cycle))`, and advances `wave` (`4 -> 5`) while triggering `survivalStageChange` (verified by `bansung-ai-waves.test.cjs` test #25).
4. **Classic `'waves'` Backwards Compatibility (`types.ts` ↔ `director.ts` ↔ `world.ts` ↔ `client`):**
   - `DEFAULT_BANSUNG_CONFIG` omits `gameMode` (`types.ts` L154), `resolveBansungGameMode` defaults to `'survival'` (`types.ts` L199–200), and `Lobby.tsx` (`L634–640`) + `game.ts` (`L1732–1766`, `L1807`) allow switching `'survival'` ↔ `'waves'`.
   - `WaveDirector` constructor defaults `opts.gameMode ?? 'waves'` (`director.ts` L844) with `BANSUNG_WARMUP_S` (`5`s) so standalone classic director callers/tests remain unaffected.
   - `world.ts` gates survival XP orbs (`L3334`, `L3378`) and `frame.srv` emission (`L4029`, `L4044`) on `'survival'`, preserves `forcePedestal` on classic Waves 4 & 7 (`L3376`), and keeps `getHud()`/`getNetPhase()`/`getNetRemaining()` classic branches (`L1111–1163`).
   - Client `store.ts` (`L1154`, `L1187`), `HudBars.tsx` (`resolveIsSurvivalMode` L181–192, `SurvivalClockStrip` gated on `isSurvival` L2647, `WavePingBanner` `suppressWaveNotice={isSurvival}` L2675, `W{wave}/10` + `rem LEFT` pills L1445–1462), and `BansungBoard.tsx` (`L315–346`, `L905–908`) cleanly isolate Survival vs Classic UI/audio.

## Verdict: **FAIL**
- Fails `c11` primarily on **F1 [MAJOR]** (double-scaled `computeBossHpMult` + late-cycle `endlessTier` leak on `boss_hunt` and classic `waves` bosses spawned via `BansungWorld`), alongside **5 MINOR** mismatches (**F2** `PostGameModal`/`finalizeResult` `Đợt 0/10`, **F3** multi-boss `pedestalDrops` anchor, **F4** `scaleMult`/`1.16` vs `1.15`, **F5** 0-indexed `Vòng 0` server log, **F6** `mobCap` 72 vs `FRAME_ENEMY_CAP` 64).
